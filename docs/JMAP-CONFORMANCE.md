# JMAP conformance tracker

This tracker records tested protocol behavior and gaps for the gateway. Each partial row covers the behavior listed in its evidence. The phase 2 gate in [PLAN.md](../PLAN.md) requires finer-grained traceability for all applicable server requirements before a full compliance claim.

## Calendar requirements

Calendar implementation uses [JMAP Calendars draft -34](https://datatracker.ietf.org/doc/html/draft-ietf-jmap-calendars-34) as a pinned draft contract and [CalDAV](https://www.rfc-editor.org/rfc/rfc4791.html) as the upstream. Read the status and dependencies again before a release claim.

| Requirement area | Status | Required evidence |
| --- | --- | --- |
| Draft §§1.5, 4 — account capability and calendar collections | Read-only preview | `Calendar/get` and `Calendar/changes` use authenticated TLS CalDAV discovery with per-account credentials and persistent state. Tests cover account scope, TLS trust, redirects, response limits, malformed upstream responses, and metadata changes. Standard capability, collection rights, preferences, and `Calendar/set` remain open. |
| Draft §§3, 5.1–5.12 — participant identities, events and synchronization | Open | ParticipantIdentity methods, CalendarEvent lifecycle and copy, query deltas, recurrence and exception mapping, time zones, attachments and round-trip updates through CalDAV with persistent IDs. |
| Draft §§5.9.2, 6, 7 — scheduling, alerts and notifications | Open | Invitation, reply, alert and acknowledgement behavior on the configured upstream, including CalendarAlert push and CalendarEventNotification methods where applicable. |
| Draft §§1.5.2–1.5.3, 2, 5.13 — conditional capabilities | Open | Determine support for sharing, availability and iCalendar parsing, and test discovery and isolation for each advertised capability. |
